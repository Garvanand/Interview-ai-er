# Personalized Recommendation Engine Architecture

## Overview
The Personalized Recommendation Engine operates directly on top of the **Candidate Skill Intelligence** layer and granular interview interaction signals. Rather than simply calculating and reporting static assessment scores, it synthesizes empirical evidence to prescribe explainable, prioritized next actions.

---

## Core Recommendation Strategies

Every recommendation maps to one of five core operational strategies:

| Strategy | Trigger Condition | Recommended Activity Example | Priority |
| :--- | :--- | :--- | :--- |
| **`next_interview`** | Strong coding correctness ($\ge 75$) but weak explanation/readability ($< 60$), or targeting candidate's lowest-assessed skill under timed interview conditions. | Architectural Walkthrough & Invariant Articulation Interview | **HIGH** |
| **`practice_session`** | Weak algorithmic reasoning (proficiency $< 60$), repeated system design deficiencies, or implementation correctness with poor complexity analysis. | Targeted Asymptotic Complexity & Space-Time Trade-off Drill / Progressive System Design Mastery | **CRITICAL** / **HIGH** |
| **`skill_reinforcement`** | Strong, steady, or improving performance ($\ge 75$) across multiple evaluated interactions. | Staff-Level Deep Dive with extreme boundary conditions and fault-injection scenarios | **LOW** |
| **`weak_signal_validation`** | Sparse signals or low model confidence (`insufficient evidence` or `low confidence`, $\le 2$ evaluations). | Targeted Diagnostic Assessment (3 focused questions across core fundamentals) | **MEDIUM** |
| **`review_prior_mistakes`** | Specific questions where the candidate failed ($< 55/100$) or specific code bugs/weaknesses were logged. | Guided Bug & Remediation Review with invariant step tracing | **HIGH** |

## Explainability Specification

Every recommendation generated by the engine is strictly deterministic and free of generic motivational filler. Each recommendation contains:

- **`target_skill`**: Concrete skill from the taxonomy (e.g., `Data Structures & Algorithms`, `System Design`, `Communication`).
- **`reason`**: Explainable rationale citing observed scores, evaluation metrics, and specific deficiencies.
- **`evidence`**: Concrete empirical data payload (question ID, problem context, test case or complexity issues, proficiency scores).
- **`recommended_activity`**: Structured actionable activity payload (activity type, title, practice progression stages, remediation steps).
- **`priority`**: `CRITICAL`, `HIGH`, `MEDIUM`, or `LOW`.
- **`expected_learning_objective`**: Clear, measurable learning outcome.

## Outcome Tracking & Performance Attribution

To determine whether the candidate followed recommendations and whether subsequent performance improved:

1. **Baseline Capture**:
   $$\text{Baseline Proficiency} = P_0$$
   Stored at recommendation creation time.

2. **Outcome Evaluation**:
   When the candidate undertakes subsequent practice or interview loops:
   $$\Delta = P_{\text{post}} - P_0$$
   - **`improved`**: $\Delta \ge +5.0$
   - **`declined`**: $\Delta \le -5.0$
   - **`unchanged`**: $-5.0 < \Delta < +5.0$

3. **Status Transitions**:
   $$\text{PENDING} \longrightarrow \text{ACCEPTED} \longrightarrow \text{COMPLETED}$$
   $$\text{PENDING} \longrightarrow \text{DISMISSED}$$

## Backend API Specification

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/api/intelligence/recommendations/<user_id>` | List recommendations with optional `?status=` and `?strategy=` filters. |
| `POST` | `/api/intelligence/recommendations/<user_id>/generate` | Generate recommendations based on candidate's skill profiles and session interaction history. |
| `PATCH` | `/api/intelligence/recommendations/<recommendation_id>/status` | Update recommendation status (`ACCEPTED`, `COMPLETED`, `DISMISSED`). |
| `POST` | `/api/intelligence/recommendations/<recommendation_id>/evaluate_outcome` | Evaluate and persist post-recommendation performance delta and outcome assessment. |
